# Contributing to WallForge

Bug reports and fixes are welcome. The most useful reports are scene wallpapers that render differently from
Wallpaper Engine; see [Reporting a wallpaper](docs/troubleshooting.md#reporting-a-wallpaper-that-renders-wrongly).

## Layout

| Path | What |
|---|---|
| `wallforge/` | The GTK4 / libadwaita app (Python). `app.py` is the window, `engine.py` starts and stops players, `library.py` scans wallpapers, `workshop.py` talks to the Steam Workshop, `weimport.py` reads Wallpaper Engine's `config.json`, `webplayer.py` is the WebKit player for web wallpapers. |
| `render/` | `wallforge-render`, the Rust renderer for video and scene wallpapers. See [`render/README.md`](render/README.md). |
| `render/tools/` | `batch.py` renders your whole library headless; `compare.py` builds contact sheets against the previews. |
| `docs/` | User documentation. |
| `packaging/aur/` | PKGBUILD. |

## Running from a checkout

```bash
./wallforge.sh                                  # the app; builds the renderer on first start if cargo is installed
cd render && cargo build --release && cargo test --release
```

The app reads `~/.config/wallforge/config.json`. To try things without touching your own settings, point it at a
scratch folder: `XDG_CONFIG_HOME=/tmp/wf-test ./wallforge.sh`.

## Testing renderer changes

Scene rendering is checked against real wallpapers, because that is where the surprises are. You need some scene
wallpapers installed through Steam.

```bash
cd render
python3 -I tools/batch.py --out /tmp/before            # before your change
cargo build --release
python3 -I tools/batch.py --out /tmp/after              # after
python3 -I tools/compare.py /tmp/after --before /tmp/before
```

`batch.py` renders each scene to a PNG without opening a window and sorts it into `works`, `partial` (a layer or
effect was skipped), `unsupported` or `fails`. `compare.py` puts before, after and the wallpaper's own preview side
by side, 16 wallpapers per sheet. Look at the sheets: a wallpaper can be in `works` and still look wrong.

A change is ready when:

- no wallpaper moves to a worse class and none that looked right looks worse,
- `cargo test --release` passes,
- the fix is general. Do not special-case a wallpaper id, name or file name. If a feature cannot be drawn correctly
  yet, skip it by a rule on the feature and print one `wallforge-render: note:` line.

One wallpaper at a time:

```bash
target/release/wallforge-render --bg <wallpaper folder> --silent \
    --screenshot /tmp/x.png --screenshot-size 1920x1080 --screenshot-time 2
target/release/wallforge-render --check <wallpaper folder>     # JSON report, no rendering
```

## Testing app changes

- Web wallpapers: `python3 -m wallforge.webplayer --bg <wallpaper folder> --window 960x540 --screenshot /tmp/x.png`
  opens a normal window, saves a PNG and exits.
- Import: `./wallforge.sh --import-we some-config.json --dry-run` prints what would be imported.

## Style

- Python: standard library plus PyGObject; no new dependencies without a good reason. Keep user-facing text plain.
- Rust: the renderer is written densely on purpose. Match the surrounding code, keep new features in their own file
  where that is natural, and avoid new crates unless they are small and pure Rust.
- Commit messages say what changed for the user, in one line, with details below if needed.

## Legal

Do not add Wallpaper Engine's files, shaders or Workshop content to the repository, including in tests. Tests use
scenes generated by `wallforge-render --make-test-scene`.
